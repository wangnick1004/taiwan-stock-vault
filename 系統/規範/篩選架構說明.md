# 異常訊號篩選架構

把每天上百則個股新聞與一千多家公司的財務數字，篩成二十家左右值得追的候選。用途有三個：付費快報的選題、題材雷達、週報的素材。程式是 `系統/scripts/訊號篩選/screen.py`，參數全部在 `系統/資料/訊號規則.json`，改參數不用改程式。

## 資料流

```
GitHub Actions（07:30、18:00、週末 09:00）
  update_news.py       → 新聞/<代號名稱> 新聞.md
  update_financials.py → 系統/資料/財務摘要.json、個股 frontmatter
  訊號篩選/screen.py   → 讀上面兩份 + 個股筆記的「產業」 + 系統/資料/0050成分股.txt
                         ├ 系統/資料/訊號/財務歷史.json   每次存一筆月營收與季報，用來比轉折
                         ├ 系統/資料/訊號/已報.json       已報過的訊號，同一訊號不重報
                         ├ 系統/資料/訊號/YYYY-MM-DD.json 當天結果（週報彙整用）
                         ├ 新聞/訊號/YYYY-MM-DD 異常訊號.md   訊號報告（見下方「報告版面」）
                         └ 新聞/訊號/題材雷達.md               近 14 天題材熱度表
```

程式只讀 repo 裡的檔案，所以雲端環境連不到證交所也能跑、能測試。真正抓資料的仍是 Actions；Actions 執行時另加 `--check-links`，實際連線檢查報告引用的連結。

## 報告版面

`新聞/訊號/YYYY-MM-DD 異常訊號.md` 是一份專業訊號報告，由上到下：

1. 報告摘要（callout）：新聞視窗、財務資料日期、候選家數、資料檢核總結果。
2. 一、訊號導覽：Mermaid 導覽圖（偏多／偏空／中性 → 個股，熱門題材、產業共振），個股節點點下去就是筆記；下面一列儀表數字和三到五點重點摘要。
3. 二、Top 候選總表：分數、方向、可信度、主要訊號、出處註腳。
4. 三、個股訊號明細：每家一張表，列出每個訊號的強度、說明、來源檢核與出處。
5. 四、題材雷達；五、產業共振；六、財務訊號總表。
6. 七、資料檢核：見下方。
7. 八、方法與限制。
8. 九、資料來源：使用的資料集，以及全部引用明細。正文用 Obsidian 註腳 `[^n]` 引用，同一出處只編一個號；每筆寫明來源、來源等級、時間、標題與連結。

## 來源檢核

每個訊號都標可信度：

| 等級 | 條件 | 媒體訊號強度係數 |
|---|---|---|
| A | 官方資料（證交所、櫃買 OpenAPI、公開資訊觀測站），或兩家以上來源交叉確認且含主流媒體 | 1.0 |
| B | 單一主流媒體；兩家以上非主流來源；或官方月營收但驗算不一致 | 0.85 |
| C | 只有單一券商平台、資訊站或聚合站來源 | 0.6 |

來源分成官方、主流媒體、券商與資訊平台、聚合與社群、其他，名單在規則檔的「來源分級」。月營收訊號另做驗算：前月營收 ×（1＋月增率）要等於本月公布值，誤差超過 2% 就降為 B 並在資料檢核列出。

## 資料檢核

報告第七節逐項檢查，結果也寫在 frontmatter `資料檢核`：

| 項目 | 怎麼檢查 |
|---|---|
| 新聞資料新鮮度 | 新聞檔「最後更新」距報告時間超過 16 小時就警示（排程延遲或失敗） |
| 新聞抓取排程 | 讀當天日報附錄裡排程留下的「本次部分來源失敗」警告 |
| 新聞來源組成 | 各等級來源的則數；平日沒有官方重訊就警示 |
| 雜訊過濾 | 排除了多少雜訊、彙整文、營收速報 |
| 新聞檔重複行 | 讀檔時略過的重複行數 |
| 財務資料新鮮度 | `系統/資料/財務摘要.json` 抓取日超過 7 天就警示 |
| 月營收覆蓋 | 多少比例的個股已有最新月份營收（月中陸續公布） |
| 月營收驗算 | 列出驗算不一致的公司 |
| 季報比較基礎 | 是否已有前一季快照 |
| 入榜訊號可信度 | A／B／C 各幾個，C 級超過兩成就警示 |
| Google 新聞轉址 | 出處是轉址連結的筆數 |
| 連結可用性 | `--check-links` 時實際連線，失敗的連結在引用明細標 ⚠️ |
| 0050 成分股名單 | 名單仍標 #待校對 時提醒 |

## 新聞視窗

預設從前一交易日 13:30 到當天結束（週一往回算到週五 13:30），可以用 `--since` 改。

## 訊號類型

| 類別 | 訊號 | 條件（預設值，可在規則檔調） | 強度 |
|---|---|---|---|
| 營收 | 年增轉正／轉負 | 前月年增 < 0 且本月 ≥ +3%；或反過來 ≤ −3% | 3 + 幅度 |
| 營收 | 成長加速 | 年增比前月多 15 個百分點以上，且本月年增 ≥ 20% | 2 + 幅度 |
| 營收 | 成長減速 | 年增比前月少 20 個百分點以上，且本月年增已低於 50% | 2 + 幅度 |
| 營收 | 高成長 | 年增 ≥ 50%，且沒有觸發上面的轉折 | 1.5 + 幅度 |
| 營收 | 累計營收轉正／轉負 | 今年累計年增變號 | 2 |
| 營收 | 月營收創新高 | 歷史檔累積滿 12 個月後才啟用 | 3 |
| 季報 | 毛利率／營益率跳升或下滑 | 同年度累計值比前一季變動 ≥ 2 個百分點 | 3 |
| 季報 | 單季轉虧為盈／轉盈為虧 | 由累計 EPS 換算單季 | 4 |
| 重訊 | A 級 | 併購、私募、減資、財測、停工、違約、訴訟、處置、變更交易方法… | 5 |
| 重訊 | B 級 | 自結損益、庫藏股、增資、可轉債、董座或總座異動、不動產、擴產… | 3 |
| 重訊 | C 級 | 注意股、法說會、會計主管或獨董異動 | 1 |
| 媒體 | 關鍵字 | 上修、調升目標價、創新高、漲價、擴產、接單、得標、轉虧… | 2 |
| 新聞量 | 暴增 | 本期 ≥ 4 則，且是前 14 天日均的 3 倍以上 | 2 + log₂(倍數) |
| 題材 | 熱門題材 | 同一題材本期出現在 ≥ 3 家公司，且是前 7 天日均的 2 倍以上 | 公司 +1 |
| 產業 | 產業共振 | 同產業營收轉折的偏多家數減偏空家數 ≥ 4，且佔產業家數 ≥ 15% | 只列出，不加分 |

季度訊號要有前一季的資料才能比較。歷史檔從這次開始累積，2026Q3 財報公布（11 月中）後才會開始出現。月營收的 8 月資料已經從 `系統/資料/公司資料` 補進來，所以 9 月的營收轉折一開始就有。

## 評分

```
訊號分 = 同一家公司的訊號強度由高到低，以 1、½、¼… 遞減加總
總分   = 訊號分 + 規模加分 + 共振加分 + 題材加分
```

- 規模加分：0050 成分股 +1；月營收 ≥ 100 億 +1、≥ 10 億 +0.5、≥ 1 億 +0.25；月營收 < 0.3 億 −1。
- 媒體訊號的強度先乘上可信度係數（A 1.0、B 0.85、C 0.6）。
- 共振加分 +2：同一家公司同時有財報訊號和新聞訊號（重訊、媒體或新聞量）。
- 題材加分 +1：這家公司的新聞碰到當天的熱門題材。
- 入榜條件是「訊號分」≥ 3，規模加分不算在內，避免大型股只靠規模上榜。通過的公司依總分排序，取前 20 名。
- 方向：把偏多、偏空的訊號依強度相加。多空都有且淨值很小時標「多空交錯」。

## 誤報控制

| 問題 | 處理 |
|---|---|
| 零股排行、三大法人、鉅額成交、技術線型貼文 | `媒體雜訊樣式` 排除 |
| 例行重訊（背書保證、資金貸與、受邀券商論壇、退還股款…） | `重訊分級.雜訊` 排除，也不算新聞量 |
| 一篇文章點名多家公司 | 標題有 3 個以上代號、4 個以上「、」，或同一標題出現在 3 家以上公司的新聞檔，就當彙整文，只算題材熱度，不幫個股加分 |
| 營收速報這類媒體轉述 | `媒體回聲樣式`，只算新聞量，營收訊號由財務資料本身判斷 |
| 多家媒體報同一件事 | 同家公司、同級別、同關鍵字的新聞合併成一個訊號，每多一則只加 0.5 分，最多加 1 分 |
| 低基期暴增（例：年增 3,425,111%） | 去年同月營收 < 0.3 億或年增 > 500% 的不列 |
| 小公司 | 月營收 < 1 億，營收訊號強度減半 |
| 同一訊號天天出現 | `已報.json` 記錄首次日期，只在第一天列出（同一天重跑會保留） |
| 新聞檔重複行 | 讀檔時同日同標題只算一次；`update_news.py` 的去重錯誤也一併修正 |

Google 新聞只抓關注清單，清單外的公司媒體新聞較少，所以新聞量訊號偏向關注清單裡的公司。

## 和日報、週報的銜接

- 08:30 盤前版：讀當天的 `新聞/訊號/YYYY-MM-DD 異常訊號.md`（07:30 排程產生），Top 候選和熱門題材是「隔夜重要新聞」「產業對照」的選材起點。
- 10:30 盤中版、13:45 收盤版：「0050 成分股要聞」優先寫 Top 候選裡的 0050 成分股（⭐），「可延伸的文章題材」從熱門題材和產業共振挑。
- 週六週報：`python 系統/scripts/訊號篩選/screen.py --vault . --week <週六日期>` 印出本週累計分數前 15 名與題材熱度，當「產業與 0050 成分股回顧」的素材。
- 訊號只是候選。寫進日報或付費文章前，仍要回原始來源確認，並沿用日報的 #待校對 規則。

## 常用指令

```bash
python 系統/scripts/訊號篩選/screen.py --vault .                       # 今天，寫檔
python 系統/scripts/訊號篩選/screen.py --vault . --check-links         # 同上，並實際檢查引用連結（要有網路）
python 系統/scripts/訊號篩選/screen.py --vault . --date 2026-10-14 --dry-run   # 看某天的結果，不寫檔
python 系統/scripts/訊號篩選/screen.py --vault . --week 2026-10-24     # 週報素材
python 系統/tests/test_screen.py                                      # 離線測試
```

## 之後可以加的

- 市值權重：Actions 多抓收盤價（證交所 STOCK_DAY_ALL、櫃買每日收盤）乘上股本，取代目前用月營收估規模的做法。
- 回測：歷史檔累積幾個月後，比對入榜後 5、20 個交易日的股價表現，再調整各訊號的強度。
