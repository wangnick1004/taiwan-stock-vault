# 每週股市統計文章：撰寫說明

建立：2026-10-23（使用者要求：每週六 09:00 從當前股市找出值得討論的圖表，寫成統計科學文章，放在 `統計/`）

## 排程與產出

| 時間（台灣） | 產出 |
|---|---|
| 每週六 09:00 | `統計/每週統計/YYYY-MM-DD <題目>.md`（日期用執行當天），圖檔放 `統計/每週統計/附件/YYYY-MM-DD_圖n_<名稱>.svg` 與同名 `.png` |

同一天週六 06:00 有台股週報（`新聞/每週/`，見 `日報撰寫說明.md`）。週報回顧一週新聞與指數漲跌；本文偏重**橫斷面或長期的統計結構**，不重述一週新聞。

## 選題方法

每次先列出 3 到 5 個候選題目，各自打分，選總分最高的一個。在文章 frontmatter 的 `選題理由` 寫一句為什麼選它。

**候選來源（依資料可得性）：**

| 題材 | 資料 | 適合時機 |
|---|---|---|
| 月營收分布、廣度、集中度 | `系統/資料/財務摘要.json`；`系統/scripts/統計/營收廣度.py` | 每月 10 日後新月份資料進來時 |
| 獲利率（毛利率、營益率）分布與變化 | `財務摘要.json` 的三率與 `財報季度` | 季報公布後（5/15、8/14、11/14、3/31 前後） |
| 估值分布（本益比、股價淨值比、殖利率） | `系統/資料/公司資料/*_本益比殖利率.json`（看檔內 Date；超過 14 天就用 WebSearch 補或換題） | 指數大漲大跌之後 |
| 價值創造（ROIC − WACC） | `統計/WACC與ROIC彙整.md` | 一年一到兩次，或與其他題材交叉 |
| 指數集中度（台積電權重、前 N 大、HHI） | `系統/資料/0050持股明細_*.csv`、`統計/0050總覽文/` | 0050 季度調整後 |
| 新聞與訊號的分布（哪些產業被討論最多） | `新聞/訊號/`、`系統/資料/訊號/*.json`、`新聞/*新聞.md` | 題材明顯集中時 |
| 市場資料（成交值、融資、外資持股、指數報酬分布） | WebSearch／WebFetch（鉅亨網可讀；證交所、Google 新聞讀不到） | 出現歷史少見的數值時 |

**評分（各 0 到 3 分）：**

1. 新鮮：有上次寫這個題材之後的新資料。
2. 顯著：數字與歷史或常識差距大（例如加總與中位數差很多、創新高或新低、分布形狀改變）。
3. 可驗證：資料在 repo 或可讀來源中，能重算。只能靠報導的題目最多 1 分。
4. 長期價值：結論或方法在一年後仍有參考價值（符合專案「10 年仍受用」的目的）。
5. 不重複：近 8 週的 `統計/每週統計/` 沒有同一題材；本週週報沒有以它為主軸。同一題材連續兩週寫，第 5 項 0 分。

## 文章結構

沿用 `統計/0050總覽文/0050總覽文.md` 的專業分析文格式（語氣正式，不寫社群貼文）：

1. frontmatter：`article_id`、`title`、`類型: 股市統計`、`data_date`、`資料期間`、`選題理由`、`paywall`、`status: draft`、`view_top`、`view_bottom`、`threads_reply`、`skip_view`、`vocus_url`、`threads_id`、`tags: [統計, 每週統計, <題材>, 待校對]`。
2. `# 標題`：陳述題目，不用問句。
3. 資料基準日 callout：每個資料來源的期間與抓取日期、樣本與排除條件、計算程式路徑。
4. 重點摘要：4 到 6 點，每點是有數字的結論並附來源編號〔n〕。
5. 一、問題與資料：要回答什麼、資料是什麼。
6. 二到四節：每節一張圖（PNG 嵌入）＋一張表＋解讀。圖 3 到 5 張。
7. 穩健性檢查：表格列出換一種算法時結論是否改變。
8. 研究限制。
9. 方法附註：公式、參數、亂數種子。
10. 資料來源：完整名稱、資料期間、連結。

寫法規則（與 0050 總覽文相同）：不用 `[[ ]]` 雙鏈，圖片用標準 Markdown；不寫預測、目標價與買賣建議（禁用詞：目標價、買進、賣出、建議買、加碼、停損、評等）；不用「# 第一章」標題；未查證或推算的內容標 #待校對。

## 統計方法清單

- 偏態資料用中位數與四分位數描述，平均數只當對照；需要時給截尾平均。
- 比例或中位數給信賴區間（自助法或二項分布），兩組比較給檢定統計量與 p 值，並說明效果大小（差幾個百分點），不只說「顯著」。
- 加總與加權：說明權重是什麼（營收、市值、家數），並至少給一個不同權重的結果。
- 集中度：前 N 大占比、累計貢獻曲線、HHI 或有效家數。
- 時間比較：同時看單月與累計（或移動平均），避免單期雜訊。

## 邏輯漏洞檢查（寫完逐項檢查，結果寫進「穩健性檢查」或「研究限制」）

| 漏洞 | 檢查方式 |
|---|---|
| 平均數被極端值拉走 | 比較平均、中位數、截尾平均 |
| 加總被少數大公司主導 | 扣除最大的一到幾家再算一次 |
| 辛普森悖論（整體與分組方向相反） | 產業或規模分組後再看一次 |
| 基期效應 | 列出年增率絕對值超過 100% 的家數，並看累計值 |
| 存活者偏差 | 說明樣本是否只含目前仍上市的公司 |
| 口徑不一致 | 營收與毛利、帳面與市值、合併與個體，說明用哪一種 |
| 相關不等於因果 | 只描述關係；推論原因時明確標為假說 |
| 多重比較 | 一次檢定很多組時，說明可能出現偶然顯著 |
| 資料日期混用 | 每個數字標資料期間，不同期間的數字不直接相減 |

## 執行步驟

1. `git pull`，讀本檔與 `00_規範索引.md`；列出 `統計/每週統計/` 近 8 週題目；讀本週週報 `新聞/每週/<今天>*.md` 的摘要（若已產生）。
2. 依上方評分選題。資料要靠程式計算的，在 `系統/scripts/統計/` 新增或沿用腳本（共用繪圖工具 `svgkit.py`）；腳本放程式、文章放結果，數字一律由腳本印出後抄進文章，不手算。
3. 產生 SVG 後執行 `node 系統/scripts/0050總覽/svg2png.js 統計/每週統計/附件/<今天>_*.svg` 轉 PNG，用 Read 看每一張圖，確認文字沒有重疊或被切掉。
4. 寫文章，逐項做邏輯漏洞檢查，再核對每個摘要數字和腳本輸出一致。
5. `git add 統計 系統/scripts/統計 && git commit`，`git pull --rebase` 後 `git push origin HEAD:main`（與 Actions 同時推送時重試，最多 4 次）。
6. 在「股市統計討論」討論串回報：題目、三句重點、檔案路徑。
